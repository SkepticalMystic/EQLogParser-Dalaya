FAQ

Common questions and their answers.

Why do some spells not appear in the Spell Counts table?

Two common reasons:

  1. Some spells produce no log message when they land on a player, so the parser has nothing to count. This is a game limitation.
  2. Some spells produce log messages that only you can see in your own log. These are hidden by default in the Spell Counts table because the main purpose of that view is to compare your counts with other players — and other players can't see those lines. To show them, use the visibility dropdown at the top of the Spell Counts tab to switch to Show All.

Why does "Unknown" or a spell name appear in the DPS Summary?

  1. Unknown player: If a DoT is ticking on an NPC when the caster dies or zones out, the log may stop attributing further ticks to a player name. These ticks are counted under "Unknown" so the total damage for the encounter remains accurate. Check the damage breakdown for the Unknown row to identify the source.
  2. Spell name in player position: In rare cases — usually when a player leaves the zone mid-fight — an older-style log entry may place the spell name where the player name should be. This is infrequent and a quirk of how the game writes certain log lines.

Why is my pet's damage not showing under my name?

Pet ownership must be established before the parser can fold a pet's damage under its owner. This happens three ways: a pre-configured petmapping.txt entry, the pet announcing "My leader is X" in group chat, or a manual assignment in the Pet Owners UI (right-click the pet's row in the DPS Summary).

Dalaya's named pets are correctly identified as pets by this fork, but ownership still needs to be confirmed via one of the three methods above. They will not be auto-assigned to your character name to avoid misattribution in raid logs.

My damage totals look too low. What could cause this?

A few things to check:

  • Logging was off for part of the fight. Any damage that occurred before logging was enabled is not in the log file and cannot be counted. Enable logging before pulling.
  • You are tailing live instead of reading from the start. If you opened the log with Now selected in the Open Log time-range menu, only events from that point onward are captured. Reopen the log and pick Everything (or a wide-enough range) instead.
  • Damage Shield (DS) damage. DS damage is only visible in the log of the player who has the DS buff. If you're looking at someone else's log, their totals won't include DS hits they couldn't see.

My overlays are not showing, or they display the wrong colors

  1. Check the Overlay configuration. Open the Overlay settings and verify that a Default overlay is checked. Triggers without a specific overlay assigned use the default one as a fallback.
  2. Preview the overlay. Use the Preview button in the Overlay settings to confirm the overlay is visible. Save any changes.
  3. Check Custom Active Color and Custom Font Color on the trigger itself. If either is set, it overrides the overlay's color settings. Even if the field shows "Click to Select Custom Color," click it and explicitly save a color or clear it.
  4. EverQuest must be in windowed mode. Overlays cannot render on top of a fullscreen EverQuest window. Switch EQ to windowed or borderless windowed mode.
  5. Check for Transparent color. A common issue is that Transparent is inadvertently selected for a color, making the overlay invisible. Set an explicit color to test, then reset if needed.

Trigger Log shows a trigger firing, but I can't find it in the Trigger Manager

Click the row in the Trigger Log — this selects and highlights the corresponding trigger in the Trigger Manager automatically, as long as the Trigger Manager is open. You can also use the Trigger Search box above the folder tree to search by trigger name or by any text in its pattern fields.

Dragging the Trigger Log and Trigger Manager tabs so they are visible side-by-side is a useful working arrangement when building or debugging triggers.

Copy or Quick Share doesn't work — nothing is copied to the clipboard

Check the error log under Tools → View Error Log for a line containing: 

ERROR EQLogParser.UIUtil - Failed to set Clipboard Text: OpenClipboard Failed (0x800401D0)

If you see this, your antivirus software is blocking clipboard access by EQLogParser. Add an exception for EQLogParser-Dalaya.exe in your antivirus settings. This is common with ESET — look for HIPS settings and add the exception there.

Where do I report a bug or ask a question?

For bugs or issues specific to the Dalaya version (parsing errors, wrong spell names, pet attribution problems), open an issue on the Dalaya fork:

github.com/SkepticalMystic/EQLogParser-Dalaya/issues

When reporting a parsing problem, always include the raw log line that isn't being handled correctly. Log files are at:

[EQ folder]\Logs\eqlog_CharacterName_dalaya.txt

For general questions about EQLogParser features that are not Dalaya-specific, the upstream project's GitHub Discussions page is a good additional resource.
