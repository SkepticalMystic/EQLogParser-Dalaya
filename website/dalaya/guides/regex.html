Regex Reference

Regular expression syntax for trigger pattern fields.

Enabling Regex on a trigger lets you write patterns that match flexible text rather than a fixed string. EQLogParser uses .NET regular expressions. This page covers the syntax you'll use most often in trigger patterns.

Basics

  • . — matches any single character (except newline). Example: a.c matches "abc", "axc", "a-c"
  • * — zero or more of the preceding element. Example: a* matches "", "a", "aa", "aaa"
  • + — one or more of the preceding element. Example: a+ matches "a", "aa" but not ""
  • ? — makes the preceding element optional. Example: colou?r matches "color" or "colour"
  • [...] — matches one character from the set. Example: [abc] matches "a", "b", or "c"
  • [^...] — matches one character not in the set. Example: [^0-9] matches any non-digit character

Anchors

  • ^ — start of the line. Example: ^You cast matches only if "You cast" is at the very start
  • $ — end of the line. Example: wears off\.$ matches "wears off." at the end of a line

Character shortcuts

  • \d — any digit (0–9)
  • \w — any word character (letter, digit, or underscore)
  • \s — any whitespace (space, tab)
  • \b — word boundary (the edge between a word character and a non-word character)

Grouping and OR

  • ( ... ) — groups elements together. Example: (cat|dog) matches "cat" or "dog"
  • | — OR — matches either side. Example: yes|no matches "yes" or "no"

Escaping special characters

A backslash \ before a special character treats it as a literal character. Example: \. matches a literal period, not "any character".

Characters that must be escaped if you mean them literally:

.  ^  $  *  +  ?  (  )  [  ]  {  }  \  |

Repetition counts

  • {n} — exactly n times. a{3} matches "aaa" only
  • {n,} — at least n times. a{2,} matches "aa", "aaa", etc.
  • {n,m} — between n and m times. a{2,4} matches "aa", "aaa", or "aaaa"

.NET regex specifics

  • No slashes — just type the pattern directly. Do not wrap it in /like this/
  • Case-sensitive by default — "cast" does not match "Cast"
  • Spaces and punctuation must match exactly as they appear in the log line
  • Named groups are supported — (?<name>...) captures into a named variable. The trigger variables {S1}, {N1}, etc. expand to named groups internally.
  • Do not use $1, $2 for group references — use the trigger variable syntax instead

Performance tips

  • Keep patterns specific — a pattern that starts with a distinctive phrase like ^Your target is far faster than one starting with .*
  • Avoid .* in the middle of a pattern unless necessary
  • Avoid deeply nested groups or complex alternations with many branches
  • Start with a fixed word or phrase from the log line — this lets the engine skip non-matching lines instantly
  • Don't write patterns that try to match entire multi-line blocks

To test a pattern against a real log line before saving a trigger, paste the line into the Test Trigger field in the Trigger Manager and run it.
