Using Raid DPS

Merging multiple player logs into a complete raid-wide view.

The Raid Damage window combines log files from multiple players and deduplicates overlapping events so you get an accurate raid-wide picture of damage dealt and healing done — without double-counting events that appeared in more than one log.

Opening the Raid Damage window

Open the Raid Damage window from the File menu or the toolbar. It opens as a separate window alongside the main parser — both can be open at the same time.

Loading log files

In the Raid Damage window, use the Add Log button (or the equivalent control) to load each player's log file. Repeat for every player whose log you have collected.

There is no fixed limit on the number of logs you can load. Load as many as you have — the more logs, the more complete the merged picture.

Load the raid leader's or main tank's log last. Since they're typically in range of all combat, their log often has the most events and provides the best baseline for the merged fight timeline.

How the merge works

When multiple players log the same damage event — for example, a wizard's nuke that three nearby players all witnessed — that event appears in all three logs. The merger detects these duplicates by comparing the event type, attacker, target, damage amount, and timestamp, and keeps only one copy.

Players' system clocks are rarely perfectly synchronized. The merger automatically detects the time offset between each log and adjusts all events onto a shared timeline before deduplication and aggregation. You don't need to do anything for this — it's handled automatically.

Reading the merged DPS view

The fight list in the Raid Damage window shows encounters built from the combined logs. Select a fight to view its merged stats. The DPS Summary works the same as in the single-player view — click a column to sort, right-click for per-spell breakdowns.

Because events from all logs are combined, players who were out of range of some events are still accurately represented as long as at least one other player's log captured those events.

Healing tab

The Raid Damage window includes a Healing tab that aggregates healing done across all loaded log files. Unlike damage records (which may appear in multiple logs and need deduplication), heal events are sourced independently per log — each player's heals are visible only in their own log or the logs of those nearby.

The merger aligns each source's heal records onto the shared timeline and combines them. The result is a raid-wide view of who healed how much and with what spells.

Limitations

  • Range visibility — if no loaded log captured a particular event (because every player was out of range at that moment), it won't appear in the merged data
  • Charm pets — charmed pets can be ambiguous in multi-log contexts; their damage may appear under different identities in different logs
  • Raid Damage is read-only — you can't modify fight boundaries or re-assign pets inside the Raid Damage window; do that in the main parser first
  • No live tailing — the Raid Damage window reads complete log files; it doesn't tail logs live while a raid is in progress
